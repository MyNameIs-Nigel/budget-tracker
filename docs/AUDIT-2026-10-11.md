## Architecture decisions

- Keep the Next.js App Router/Better Auth/Drizzle/PostgreSQL structure and current
  server/client boundaries. Owner-scoped access, fresh disabled-state checks,
  no shared financial cache, and per-owner ledger locks remain appropriate.
- Keep the plan as versioned JSONB and checking as a separate versioned checkpoint.
  These support explicit saves and reconciliation without inferring bank balances
  from forecasts. No schema or applied migration changes were necessary.
- Extend transaction helpers to reuse an existing connection so a locked write
  does not acquire a second connection from the small pool. Snapshot checks run
  under the same lock as imports, so import changes also invalidate stale edits.
- Centralize test-connection guards and JSON limits. The browser runner validates
  before migration/build, supplies fictional auth/provider settings, and starts
  its own server. Add PR CI with disposable PostgreSQL, migration integration,
  browser tests on both viewports, and lint/type/format/unit checks.
- Expand `AGENTS.md` with the code map, installed Next.js documentation requirement,
  local setup, regression protocol, exact test commands, data/privacy contracts,
  and deployment boundaries. Preserve the generated Next.js instruction block.

## Limits and compatibility

- PATCH now requires `expected` alongside new transaction fields; DELETE requires
  JSON `{ expected }`. The updated client sends the previously read row. An old
  open tab or API caller without this snapshot fails validation and must reload
  or update its request; it cannot silently overwrite newer data.
- The ledger still loads full history and calculates running balances in the
  browser. Large-account pagination/server aggregation is a future scaling task;
  no production-size benchmark or bank integration was performed.
- Plans and forecasts retain the documented monthly estimates and separate
  snapshots. This audit does not validate real-world bank/interest calculations
  beyond those explicit model assumptions.
- Full `npm audit` reports one upstream `braces` advisory through five development
  dependency entries in Next.js lint tooling. The suggested automated "fix"
  downgrades `eslint-config-next` to 14, so it was not applied to this Next.js 16
  app. Production dependencies are unaffected by that report.
- Live Google OAuth, Neon, and production deployment were not exercised. Remote
  CI/preview results are reported separately in the PR. This change does not
  authorize a production deployment or merge.
